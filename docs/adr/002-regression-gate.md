# ADR-002：回归门禁的判定模型

- 状态：已采纳（阶段 2，阶段 3 增补成本与基线约束）
- 关联：[指标定义 §7](../project-plan.md#7-指标定义简历数字都从这里来)、[面试素材 §10](../project-plan.md#10-面试素材)

## 背景

门禁要同时满足两个相反的要求：

1. **不能放过退化**：Prompt 或模型一改，通过率掉下去必须拦住，并能定位到用例；
2. **不能误伤**：单条 flaky 用例、用例集正常增删、成本小幅波动都不该阻断合并。

只用"通过率跌幅"一个阈值时，两个要求会互相拉扯：阈值放宽就漏拦，收紧就误伤。

## 备选方案

| 方案 | 说明 | 问题 |
|---|---|---|
| 只比通过率 | `candidate - baseline` 低于阈值即 block | 4 条用例里掉 1 条就是 25%，阈值无法同时适配大小用例集 |
| 只比 New Failures | 基线通过、候选失败即 block | 用例集扩容后分母变化会导致误判，且无法表达"允许少量波动" |
| 绝对分数门槛 | Pass Rate < 0.9 即 block | 与基线无关，无法反映"这次改动带来的增量退化" |
| **New Failures + Regression Delta + 成本上限** | 三条件组合，任一越界即 block | 规则更多，需要清晰的判定与退出码 |

## 决策

判定读的是**基线运行**与**候选运行**两份快照，按 `case_key` 对齐（不按用例序号、不按名称）：

- **New Failures**：基线 `passed`、候选 `failed/error` 的用例集合，必须逐条列出；
- **Regression Delta**：`candidate_pass_rate - baseline_pass_rate`；
- **Cost Delta**：单次运行成本相对基线的涨幅；
- **用例集变更**：新增 / 修复 / 移除分别列出，`allow_removed_cases` 控制删除是否阻断；
- **Judge 可信度**：`require_kappa` 开启时，κ 未达阈值直接 block，而不是"先信后补"。

规则来自 `gates/*.yaml`，默认 `max_pass_rate_drop: 0.02`、`max_new_failures: 0`、`max_cost_increase: 0.20`。

判定结果三态，并与进程退出码绑定：

| verdict | 含义 | 退出码 |
|---|---|---|
| `pass` | 所有规则满足 | 0 |
| `warn` | 未越界但存在提示（如用例集变更、κ 样本不足） | 0 |
| `block` | 任一硬规则越界 | 2 |

配套约束：

1. **只有 `succeeded` 的运行能被设为基线**，避免把超时/中断的半成品当参照；
2. 基线是**显式操作**（`--baseline` 或 `POST /runs/{id}/baseline`），不自动滚动；
3. 断言失败属于评测结果，不改变运行状态；执行异常才写 `failed`，两者在报告里分开统计；
4. 门禁只做判定，不做重试——重试会掩盖 flaky，重跑必须是显式行为。

## 后果

正面：

- 拦截理由可以直接贴进 PR：`New Failures 3 条，超过允许的 0 条`、`通过率跌幅 75.0%，超过允许的 2.0%`；
- 用例集扩容不会因为分母变化误伤（新增用例单独列出）；
- CI 只需判断退出码，不需要解析自然语言输出。

负面与约束：

- 需要人工维护基线，基线漂移（长期不更新）会让 Delta 失去意义；
- `max_new_failures: 0` 在真实模型上偏严格，接入真实 SUT 时应配合 flaky 统计调整阈值；
- 门禁不解决 flaky 本身，只能通过"同一用例重跑 N 次"把不稳定单列（见 ADR-003）。
